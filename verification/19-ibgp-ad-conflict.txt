============================================================
Phase 3: iBGP Administrative Distance (AD) Conflict Resolution
============================================================

Problem:
  External BGP routes were showing as 'r>' (RIB-failure) in the BGP table.
  Reason: OSPF (AD=110) was preferred over iBGP (AD=200) for the same prefixes.

Root Cause:
  R1-Core redistributes BGP into OSPF (redistribute bgp 65001 subnets).
  IOS automatically tags redistributed BGP routes with the originating AS (65002).
  R2-iBGP learned these routes via OSPF (AD=110) and also via iBGP (AD=200).
  OSPF won the AD comparison, so the iBGP routes were not installed in the RIB.

Solution:
  Filter out OSPF routes with tag 65002 on R2-iBGP using a route-map.
  This prevents R2-iBGP from learning external BGP routes via OSPF.
  The iBGP routes (AD=200) then become the only candidates and get installed.

Configuration on R2-iBGP:
  route-map RM-BGP deny 10
   match tag 65002
  route-map RM-BGP permit 20
  !
  router ospf 1
   distribute-list route-map RM-BGP in
